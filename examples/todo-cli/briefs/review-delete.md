# 리뷰 실습: 할 일 삭제

## 시작 조건

Lead가 고정한 실제 기준 SHA와 후보 SHA, 리뷰 경로, Worker 인계 및 테스트 근거를 먼저 확인한다. 이 브리프 자체에는 아직 리뷰할 SHA나 통과 결과가 없다. 주입된 작업 정보에서도 실제 값을 확인할 수 없다면 리뷰 대상 미확정으로 보고한다. SHA를 만들어내거나 현재 HEAD를 임의 승인 대상으로 삼지 않는다.

## 검토 범위

- `src/**`와 `test/cli.test.js`의 `delete <id>` 변경을 기준·후보 SHA 사이에서 검토한다.
- tracked·staged·untracked 상태도 확인해 고정된 후보 밖 변경을 식별한다. 후보 밖 변경은 승인에 포함하지 않는다.
- 기존 `add`, `list`, `done` 및 `--file JSON_PATH` 동작이 유지되는지 확인한다.
- 삭제 성공·영구 저장, 없는 ID·누락 인자의 오류와 무변경 보장, 다른 항목 보존, 완료된 항목·마지막 항목 삭제, 삭제 뒤 추가와 ID 충돌 방지를 확인한다.
- 테스트가 임시 데이터를 사용하는지, 실제 CLI를 호출하는지, 저장소 재로딩을 확인하는지 검토한다. 전체 `npm test` 실행 근거가 후보 상태와 일치하는지 확인한다.

## 결과

plan 모드에서 코드·설정·문서·git 상태를 바꾸지 않고 텍스트로 반환한다. 직접 테스트하지 않았다면 제공된 근거를 검토했다고 명시한다.

최종 응답에 실제 기준 SHA와 후보 SHA, 작업 트리 상태, 발견 사항의 심각도·파일·줄·재현 조건·영향·수정 방향, 테스트 근거와 공백, 수정 필요 여부를 담는다. Lead가 결과를 기록한다. 발견 사항이 없더라도 검증 공백을 생략하지 않는다.

이 리뷰는 요구사항을 알고 수행한다. `shower` 검토로 간주하지 않는다.

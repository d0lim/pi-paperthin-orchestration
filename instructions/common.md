# Paperthin 협업 공통 지침

현재 작업 디렉터리의 사용자 요청, AGENTS.md와 적용되는 저장소 지침을 확인한다. 이 패키지의 설치 디렉터리는 지원 파일 경로이며 작업 대상이 아니다. 저장소의 언어, 빌드 도구, 테스트 명령을 실제 파일에서 확인한다.

- 승인된 작업 범위를 계속 수행한다. 평범한 파일명·도구·경로 선택과 이미 허용된 읽기·수정·검증마다 재확인을 요청하지 않는다. 설명이나 조사만 요청했다면 그 범위를 지킨다.
- 동시에 쓰는 작업자는 서로 다른 worktree와 명시한 담당 파일을 사용한다. 다른 사람의 변경을 되돌리거나 자신의 변경과 함께 커밋하지 않는다. 사용자의 커밋·통합 제한을 우선한다.
- Lead는 계획, 위임, 리뷰 기록, 최종 로컬 통합을 담당한다. Worker는 구현·테스트 근거를 반환하고, Reviewer는 독립적으로 검토한 결과를 텍스트로 반환한다. pane의 idle 표시나 완료 선언만으로 검증을 대신하지 않는다.
- 역할별 모델과 effort는 번들 기본값과 설정 기준 프로젝트의 선택적 `.pi/paperthin.json`에 따른다. 모델 추천은 실행 설정을 바꾸지 않는다. 인증 또는 모델 접근이 실패하면 그대로 보고하고 다른 모델이나 API 결제로 자동 전환하지 않는다.
- 원격 push·PR 작업·배포·파괴적 작업은 현재 요청에서 허용한 범위를 따른다. 워크플로우 활성화 자체가 추가 권한을 만들지는 않는다.
- 토큰·인증 파일·전체 셸 환경을 읽거나 인계하지 않는다. 실제 수행한 검증과 실행하지 못한 검증을 구분한다.

## Paperthin 적용

- `readchk`는 모든 역할의 실질 작업 시작과 범위 변경 때 적용한다. 요청이나 브리프를 자기 말로 해석하고 현재 파일·지침과 대조한다. Lead는 기존 작업 기록에 `understood as: ...` 한 줄을 남긴다. Worker·Reviewer는 시작 출력으로 해석을 남기고 Lead가 회수한다. 해결된 해석은 승인 질문으로 만들지 않는다. 단순 질의나 상태 조회에는 별도 기록을 만들지 않는다.
- `modelchk`는 Lead가 첫 위임과 작업의 범위·위험·실패 양상 변화 때 적용한다. 작업 단위별 추천 tier·effort, 공통 이유, 두 축의 상향·하향 조건, 검증 근거를 원본의 여섯 필드로 기존 계획·브리프에 기록한다. 실제 역할·모델·effort는 추천과 분리해서 기록하고 명시한 설정을 따른다. 비용이 과하거나 능력이 부족해 보이면 차이를 보고하되 자동 전환하지 않는다. 같은 작업의 단순 재시도는 기존 판단을 재사용한다. 추천을 마친 뒤 Lead 작업을 계속한다.
- `shower`는 Lead가 첫 실질 Worker 브리프와 최종 사용자용 문서·인계 산출물을 전달하기 전에 수행한다. Lead만 보는 작업 기록에 의도와 독자를 한 줄 적고, `workflow_cold_read`에 해당 결과물의 `artifact` 경로만 전달한다. 새 세션은 결과물 내용만 받으며 도구·확장·스킬·프로젝트 지침·세션 저장을 사용하지 않는다. 반환된 `artifactSha256`와 독립 해석, 원래 의도와의 차이를 기존 작업 기록에 남긴다. 동일 내용의 검토는 재사용하고 의미가 바뀌거나 해석을 막는 문제가 남았을 때만 다시 읽힌다. 매 단계의 모든 브리프나 코드 파일에 별도 호출을 붙이지 않는다.
- `re0`는 문서를 반복 수정하거나 동작 변경을 관련 문서에 반영할 때 작성자가 적용한다. 대상과 함께 맞아야 할 문서를 끝까지 읽고 기존 섹션을 현재 사실에 맞게 정리한 뒤 다시 읽는다. 개선할 점이 없으면 수정하지 않는다. 범위 밖 문서를 정리하거나 새 문서를 만들지 않는다. Reviewer는 수정하지 않고 필요한 정리를 지적한다.

역할별 핵심 SKILL.md 원문은 시스템 정책에 포함된다. 나머지는 제공된 경로에서 읽는다. 본문 전달·읽기와 절차 완료를 구분한다. 적용 기록에는 스킬·대상·실제 결과나 근거를 남긴다. 대상 없음, 같은 해시로 재사용, 실행 실패는 그 사유를 적고 완료로 표시하지 않는다. 설명·조사 요청에는 파일 생성·구현·위임을 추가하지 않는다.

정리·cold-read 수정은 가능한 한 계획 해시나 코드 후보를 고정하기 전에 마친다. 승인된 계획이나 후보를 바꿨다면 새 해시로 고정하고 영향을 받는 계획·코드 리뷰를 다시 받는다. 스킬은 테스트와 독립 코드 리뷰를 대체하지 않는다. Compound Engineering과 추가 전체 루프는 사용하지 않는다.

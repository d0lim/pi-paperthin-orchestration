# 구현 실습: 할 일 삭제

## 목표

기존 JSON 기반 할 일 CLI의 `add`, `list`, `done` 동작을 유지하면서 `delete <id>` 명령을 추가한다. 데이터 파일은 기존 `--file JSON_PATH` 옵션을 사용한다.

## 시작 조건과 담당 범위

- Lead가 지정한 별도 worktree에서 실행한다. 시작 시 현재 경로, 실제 HEAD SHA, 작업 트리 상태를 확인하고 인계에 기록한다. 경로나 기준이 불명확하면 임의 브랜치를 수정하지 말고 보고한다.
- 수정 가능한 파일은 `src/**`와 `test/cli.test.js`다. 다른 작업자의 변경을 되돌리지 않는다.
- 지침, 역할 설정, 의존성, 실행 스크립트, 문서, Lead 브랜치는 수정하지 않는다. 다른 에이전트를 재위임하지 않는다.
- 기존 ID 형식, 출력, 오류 코드 규약을 먼저 읽고 따른다. 요구사항 해석이 모호하면 `readchk`를 읽고 적용한다.

## 완료 조건

1. `delete <id>`는 해당 할 일 하나를 JSON 저장소에서 제거하며 저장 후 다시 조회해도 삭제 상태가 유지된다.
2. 존재하지 않는 ID와 ID 누락은 기존 CLI 방식에 맞는 명확한 오류로 처리하며 파일의 기존 내용을 바꾸지 않는다.
3. 삭제 후 다른 할 일의 ID·제목·완료 상태가 유지된다. 완료된 할 일과 마지막 하나뿐인 할 일도 삭제할 수 있다.
4. 삭제 뒤 새 항목 추가가 정상 동작하고 ID가 충돌하지 않는다. 기존 `add`, `list`, `done` 테스트가 계속 통과한다.
5. 테스트는 임시 디렉터리의 데이터 파일을 사용한다. 성공·오류·보존·재로딩 사례를 실제 CLI 실행으로 검증하고 `npm test` 전체를 실행한다.

## 인계

커밋하지 않는다. stdout 최종 응답으로 작업 경로, 실제 기준 HEAD SHA, 변경 파일, 구현 내용, 테스트 명령과 실제 결과, 남은 문제를 보고한다. 담당 범위 밖에 인계 파일을 만들지 않는다. Lead가 통합 후보를 고정하고 리뷰를 진행한다.

# 검증 기록

확인일: 2026-09-14 · 패키지 버전: 0.3.0

## 현재 패키지

- `npm test`: 40개 통과, 실패·skip 없음. 실행기 17개, 확장 13개, 패키지 로더 4개, 선택 예제 6개를 포함한다.
- 실제 설치된 Pi 0.85.1의 로더로 임의의 임시 프로젝트에서 패키지 확장 1개와 Paperthin 스킬 4개를 확인했다. 같은 확장의 명시 경로 중복 제거와 `--no-skills`도 확인했다. Pi가 별도로 탐색하는 사용자 스킬은 패키지 기여분과 구분했다.
- 확장 테스트는 일반 Pi 비활성 상태, 정확한 Lead 모델 선택·인증 실패, 취소·대기, 명시한 역할 검사, `/workflow off`, 세션 활성 상태 복원과 대상 경로 일치를 확인한다. 모델 선택과 호출은 모의 API로 검사했다.
- 실행기 테스트는 임의 프로젝트 지침 경로, 설정 상속, 잘못된 설정 거부, worktree로 전달되는 설정 기준, Claude plan 모드, 정확한 Herdr 인자, cold-read 격리, 셸 미사용, Paperthin 원본 체크섬을 확인한다. Pi·Claude·Codex에 역할별 원문 전체가 실제 인자로 포함되고 다른 역할의 본문이 추가되지 않는지도 검증한다.
- cold-read 응답은 `artifact`, `artifactSha256`, `interpretation`으로 읽은 대상을 식별한다. 해시는 모델에 전달하는 내용과 동일한 파일 스냅샷에서 계산하며, 호출 준비 후 파일이 바뀌어도 기존 내용과 해시가 짝을 이루는지 검사했다. 해시와 본문 전달은 실제 독해나 절차 완료를 증명하지 않는다.
- `npm pack --dry-run --json --ignore-scripts`: 확장·런타임·설정·지침·보조 CLI·문서·Paperthin 원본과 라이선스가 배포 대상에 포함된다. 예제 앱과 로컬 실행 기록은 패키지 배포 목록에 포함하지 않는다.

## 실제 Paperthin 적용

이번 변경에서는 `readchk`로 요청을 “기존 설치형 workflow에서 스킬 본문·적용 시점·증거를 연결”하는 작업으로 해석했다. `modelchk`는 `standard`·`thorough`를 추천하고 위험 변화 조건과 검증 근거를 기록했으며 실제 역할 모델은 바꾸지 않았다. `re0`로 README·Runbook·참조 문서를 전체 재독해 같은 운영 절차로 맞췄다.

실제 Pi/Sol cold-read 호출에 README 내용만 전달했고 종료 코드 0과 빈 stderr를 확인했다. 첫 독립 해석은 `minor gaps`로, Lead pane과 자식 실행 주체, 작업 기록 위치가 불명확하다고 지적했다. 원래 의도와 비교해 해당 안내와 모델 호출 없는 설치 확인을 보완했다. 원본 응답과 읽은 문서 해시는 Git에서 제외한 `.agent-runs/paperthin-readme-shower.json`에 남겼다.

수정본도 새 독립 세션에서 재검토했다. SHA-256 `424d3ad1598710c105dfd9773262ff2b54c697eb305a0a3376dac4d12195b44c`, 종료 코드 0, 판정 `minor gaps`였다. 독립 독자가 Lead·자식 실행과 기록 경로를 명확히 설명했고 준비된 Pi·Herdr 사용자가 핵심 흐름을 이해할 수 있다고 판단했다. 상세 설치·복구·전체 설정 설명과 실제 E2E 여부는 여전히 연결 문서와 별도 검증에 의존한다. 이 결과를 완전한 운영 검증 통과로 표시하지 않는다. 재검토 원본은 `.agent-runs/paperthin-readme-shower-recheck.json`에 남겼다.

## 이전 확인과 남은 범위

프로젝트 전용 확장이었던 이전 버전에서 실제 Pi/Sol Worker와 Claude Code/Opus Reviewer의 읽기 전용 호출, 역할 인식, readchk 본문 읽기를 확인했다. 이 결과를 새 패키지의 전체 다중 에이전트 실습 성공으로 간주하지 않는다.

현재 패키지의 실제 Astra Lead 작업, 계획 리뷰부터 단계별 구현·코드 리뷰·통합까지의 Herdr E2E, Fable·Codex 선택 역할은 아직 수행하지 않았다. cold-read 실호출은 런타임이 생성한 인자로 수행했으며 확장 도구 핸들러는 모의 API로 검증했다. 이 검증을 전체 역할이 모든 Paperthin 단계를 준수했다는 증명으로 해석하지 않는다. 승인 순서를 강제하는 별도 상태 머신이나 자동 작업 재개 엔진을 구현한 것은 아니다.

Herdr 밖에서 사용 중인 pane을 조작하지 않았다. 모델 이름의 자기 보고와 세션 모델 설정은 독립적인 서버 모델 정체 증명을 대체하지 않는다.

## 설치 확인

전역 패키지 등록은 `pi list`로 확인하고, 업데이트 후 새 Pi 또는 `/reload`로 명령을 다시 로드한다. 설치 로그와 기타 로컬 점검 기록은 Git에서 제외한 `.agent-runs/`에 둘 수 있다.

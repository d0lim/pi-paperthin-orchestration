# 검증 기록

확인일: 2026-09-15 · 패키지 버전: 0.5.0

## 자동 검증 범위

`npm test`로 런타임·설치·상태 전이를 검증한다. Pi SDK 0.85.1은 격리된 테스트 경로에 설치해 `PI_PACKAGE_DIR`로 지정했다. 일반 개발 환경에서 SDK가 없으면 설치 검사가 skip될 수 있으므로 CI도 같은 SDK를 설치한다. 별도 lint/typecheck 명령은 없다. 실제 Pi 로더가 TypeScript 확장을 불러오는 검사와 등록된 도구를 통한 전체 승인·완료 흐름을 포함한다.

- 기존 동시 실행·대기 한도, 시간 제한, 취소, 세션 종료, 소유한 자식 프로세스 정리 검사를 유지한다.
- 계획 리뷰→구현→작업 리뷰→통합→최종 검사→통합 리뷰→완료를 **실제 Git 저장소, worktree와 Node 자식 프로세스**로 실행한다. 모델 응답만 고정 fixture로 대체한다.
- 계획 승인 전 구현, 검사 없는 리뷰, 최종 통합 리뷰 없는 완료를 거절한다. 계획 본문·저장된 스냅샷·후보 SHA가 바뀌면 기존 승인을 재사용하지 않는다.
- 공백·개행을 포함한 실제 파일명 소유권, 의존성·중복 실행, 실제 의존 작업 merge 충돌과 명시적 해결, 시도 상한, 죽은 세션의 고아 작업, 살아 있는 controller lease를 검사한다.
- controller 인계와 worktree 생성 전후에 별도 프로세스를 강제 종료해 복구를 검사한다. 저장소·기준 SHA가 다르거나 무관한 파일이 있으면 생성을 이어받지 않는다.
- 검사는 전달된 argv를 비동기로 실행한다. 다른 job의 시간 제한·정상 종료, 검사 중 후보 잠금, 취소·세션 종료, 출력 8 MiB 초과와 자식 프로세스 정리를 검사한다. 검사 결과는 명령·종료 코드·출력과 함께 해당 후보와 계획에 연결된다.
- 단계별 기본 프로필, 사용자 profile/effort pin 우선, 설정 변경 경쟁 시 실제 모델·provider·effort 일치, Fable headless 차단을 검사한다. 시험용 저장소의 허용 설정은 실제 사용자 설정을 변경하지 않는다.
- 리뷰 JSON의 단계·계획 해시·base/candidate SHA·판정·결함 형식을 검증한다. 종료 코드 0, 자유 형식의 “승인”, 모델 불일치, permission denial은 승인으로 인정하지 않는다.
- 관리 실행 프롬프트에 실제 계획 스냅샷과 검사 근거가 들어가는지, 마지막 CLI 인자가 전체 프롬프트인지 확인한다.
- Herdr 어댑터는 모의 CLI 응답으로 검증한다. 명시한 workspace에 새 탭을 만들고 검증된 새 pane에만 시작·프롬프트 명령을 보낸다. 오류 시 생성된 탭을 보존하며 불확실한 입력을 재전송하지 않는다.
- 비용·토큰 집계는 실제 보고값만 더한다. 미보고 수치를 0으로 대체하거나 임의 가격을 적용하지 않는다.
- 임의 프로젝트에서 실제 Pi 패키지 로더로 확장과 Paperthin 28개를 로드한다. 원문 체크섬, model 16개·user 12개의 호출 경계, 선택한 스킬 본문, `/lead` 전 비활성 상태를 검사한다.

검사 결과와 독립 코드 리뷰의 결론은 해당 변경의 PR에 기록한다. `npm pack --dry-run --json --ignore-scripts`로 새 런타임 모듈·설정·지침·문서·원문 스킬과 라이선스의 포함 여부를 확인한다. 테스트·실행 로그·인증 파일은 패키지 배포 목록에 포함하지 않는다.

## 실제 호출과 운영 검증의 경계

이 변경에서는 Astra·Sol·Opus·Fable 모델을 실행한 전체 흐름이나 실제 Herdr 탭 조작을 검증하지 않았다. 확인한 로컬 CLI는 Herdr 0.9.0, Codex 0.154.0, Claude Code 2.1.269이며, 도움말과 Herdr의 번들 API 계약을 어댑터 근거로 사용했다. SDK 로더 검사는 Pi 0.85.1을 사용했다. 모델 제공·인증·구독 조건은 실행 환경에서 별도로 확인해야 한다.

v0.4.0의 실제 Pi/Sol 호출 및 독립 읽기 기록은 [이전 검증 문서](https://github.com/d0lim/pi-paperthin-orchestration/blob/abab11d9835ce91ea23e173b8eec44b4ba16ce37/docs/verification.md)에 남아 있다. 이 버전의 전체 흐름 검증으로 간주하지 않는다.

상태 원장은 승인 대상과 실행 근거의 연결을 강제한다. 테스트가 제품 요구를 충분히 검증하는지, 리뷰 모델이 결함을 놓치지 않았는지까지 증명하지는 않는다. 원장은 로컬 파일 권한 안에서 보호하며, 사용자가 직접 파일을 변조할 수 없는 보안 저장소는 아니다.

## 설치 후 점검

새 Pi 또는 `/reload`로 명령을 다시 로드하기 전에 진행 중인 관리 작업을 완료하거나 취소한다. `/lead --help`, `/workflow`, `/workflow jobs`, `/workflow skills`로 명령과 상태를 확인한다. `/lead` 활성화 후 `/workflow runs`에서 영속 기록을, `/workflow metrics`에서 현재 세션의 실행 집계를 확인한다. 세션이 비정상 종료됐다면 원장과 작업 공간을 확인하고 복구 사유를 기록한 뒤 새 작업을 제출한다.
